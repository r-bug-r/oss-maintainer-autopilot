01

The loop

Four steps. One signature.

The approval gate is enforced by the state machine, not by a prompt. Every proposal has an owner, a role check, an expiry, and a record in the audit chain.

  1. 01

    Receive

    A signed webhook is verified, replayed deliveries are rejected, and duplicates are dropped before they reach a workflow.

    POST /webhooks/github
  2. 02

    Draft

    The model answers into a closed schema. The result is stored as a proposal with citations, a risk level, and an expiry — never as a side effect.

    autopilot triage --issue 41
  3. 03

    Sign

    A named actor with a repository role approves or rejects. The decision is recorded; approval does not execute anything by itself.

    autopilot approve <id>
  4. 04

    Apply

    An approved proposal is claimed with a conditional update, executed once, and appended to the chain. A second click finds it already claimed.

    autopilot apply <id>
02

What it drafts

Drafted, not posted.

Every workflow produces the same kind of artifact: specific enough to approve quickly, small enough to reject without argument.

Issue triage

comment + labels
A summary, labels from your taxonomy, missing-reproduction questions, and duplicate candidates scored deterministically before the model is called.

Pull request review

review comment
A review note that quotes the changed lines it reasons about. It becomes a comment on the pull request only after approval.

Release notes

release draft
Draft notes assembled from merged pull requests, with every entry linked back to the pull request it came from.

Spend ledger

every call
Per-repository daily and monthly budgets are checked before a provider call. Cache hits and failures are recorded too, not only the calls that worked.
03

Safety

Built to refuse.

The safe path is the only path the code allows. These are invariants with tests, not configuration defaults.

01

No unapproved side effects

A forge call can only originate from an approved proposal, claimed by a conditional update. A repeated click cannot post twice.

02

Untrusted text stays data

Issue bodies are framed as data, never instructions. Model output must match a closed schema that rejects unknown fields and actions.

03

Budget before spend

Limits are checked before the provider call. The ledger records failures and cache hits, so the cost report cannot quietly undercount.

04

Fail closed

A missing webhook secret, an invalid signature, or a live provider without explicit opt-in raises. It does not degrade into something weaker.

04

Five minutes, no token.

The default provider is deterministic and local. The fixture adapter writes comments to SQLite, so this walkthrough cannot touch GitHub.

Full quick start and commands
quick start · python 3.12 
$ python -m venv .venv
$ . .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
$ pip install -e ".[dev]"

$ export AUTOPILOT_HOME="$PWD"
$ python -m autopilot demo seed
$ python -m autopilot triage --repo github:demo/autopilot-sandbox --issue 41

# review the draft, then sign it
$ python -m autopilot proposals --state pending_approval
$ python -m autopilot approve <proposal-id> --actor demo-maintainer
$ python -m autopilot apply <proposal-id> --actor demo-maintainer

$ python -m autopilot audit verify
