Status: accepted

## Decision

The console in `src/autopilot/ui/` is now the designed surface for the routes
that already existed. No route, endpoint, payload, or persisted field changed.
The design work is confined to three files: `index.html`, `styles.css`, and
`app.js`.

The memorable structural element is the **decision rail**: one row per proposal
showing `received -> analyzed -> proposed -> approved/rejected -> applied`, drawn
vertically on the detail screen and as a horizontal strip on narrow widths. It
is the trust boundary of the product, so it is the thing that identifies the
interface after the logo is removed.

## What the interface must never do

These are enforced by construction in `app.js`, not by convention:

- An approve or reject control is only rendered for `pending_approval`. Every
  other state renders as text, so there is no disabled-but-present destructive
  control to mis-click.
- The confirmation dialog restates the exact side effect, target, actor, and
  expiry before the action is submitted, and disables its own buttons while the
  request is in flight.
- Risk and status are always spelled out as text. Colour is a second signal, so
  the queue is readable in greyscale and to a screen reader.
- No metric is invented. With zero model calls the overview says so instead of
  drawing a trend line.

- **Keyboard-only pass**: tab order is header controls, then navigation, then
  main content; focus is visible on every stop via `:focus-visible`. The

  queue, detail, dialog, audit, and settings, and inspected for overlap,
  clipping, and ragged alignment. Two defects were found and fixed: the filter
  bar's clear button was laid out outside the toolbar, and the clear button
  stayed enabled while doing nothing.

## Deliberate choices that trade against the plan

- **The action bar is in normal flow, directly after the "Will change" block**,
  not sticky. The plan allows either. Keeping the side effect on screen at the
  moment of the decision is the property that matters; a sticky bar detaches the
  button from the evidence and covers content at 320px.
- **No bulk selection, no trend charts, no fabricated activity.** The plan
  forbids the first two for this version and the third outright.
- **The queue keeps a table at >=768px and becomes a stacked card list below
  it.** A horizontally scrolling table at 320px would technically avoid page
  overflow while making the risk and status columns unreachable without a
  gesture.

## Known limitations

- **No screen-reader run on a real assistive technology.** The axe rulesets and
  the DOM review (landmarks, headings, labelled controls, `aria-live` status
  region, dialog semantics) passed, but no NVDA/JAWS/VoiceOver session was
  recorded. This is the one item in the shared gate that is not evidenced by an
  observed run.
- **Screenshots are working artifacts**, not committed fixtures. They live in
  `.ui-verify/`, which is gitignored.
- **Git history starts at the real date.** See the Phase A record: no commit is
  backdated and no synthetic history is created.
